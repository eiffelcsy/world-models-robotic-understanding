Four things found in this review

I checked each of these against the cached pilot outputs. None needs new clips: everything below can be re-scored from the clips and GT already on disk.

Depth 0.357 vs 0.359

Feed the untouched input photo through gray_depth and score it, and it gets δ¹ 0.357. Veo gets 0.359. The current depth number cannot tell a model that drew a depth map from one that did nothing.

Robot keypoints 27.5 dots / 7 joints

The extractor finds about 24 saturated blobs in the raw input frame alone, so the null PCK is 0.214. PCK equals recall under nearest-first matching, so extra blobs inflate it, and precision is only 0.065. The readout-to-oracle gap (0.26 → 0.48), which the midterm reads as drift, is probably mostly this effect.

RoboPEPP ground truth 17 / 140 off-frame

12% of GT keypoints (in 11 of 20 items) and 10 of 20 pose targets fall outside the 1280×720 image. GT ran with no robot bbox and with guessed intrinsics (f = 1.2·max(H,W)). A model cannot draw a dot outside the frame.

Active object vs instance seg 14 / 17 identical GT

Both probes paint {relevant_objects} (target + destination) and are scored against the same gt_prompt. As configured, the "Interaction" task mostly repeats the "Scene" task.

Null baseline: the conditioning frame scored as though it were the generated output, using each probe's own extractor, metric and cached GT. Computed with a throwaway script run in the repo venv. It is not part of the repo yet: step 1 below adds this baseline to the report properly.

Evaluation protocol shared by every probe

conditioning frame ──GT source (specialist model)──▶ pseudo-GT ──┐ cached: <gt_dir>/<probe>_gt/<id>_gt.npz ├──▶ metric ──▶ scores (+ best_* oracle scores) generated clip ──readout──▶ one frame ──extractor──▶ prediction ──┘ └──▶ fidelity gates (flag only, never change the score)
Ground truth
Computed from the conditioning frame only, so the generated video can never leak into it. Stored as .npz plus a preview .png, and reused on later runs. Changing a param does not invalidate stored GT; the run only logs a warning. To regenerate, delete the file or run the module's preview.py.
Readout
Picks one frame without looking at the GT. last_frame (back_off=1) for five probes. Depth uses most_static: the frame with the smallest diff from the frame 2 steps before it, within the last 2.0 s. fixed_time also exists but is unused.
Oracle frame
The extractor and metric run on every frame (stride 1) from index 5 onward, keeping the frame with the highest rank_by score. Reported as best_*. It is an upper bound chosen using the GT, so it is not a deployable score. Frames 0–4 are skipped because they still show the conditioning image.
Resolution
The prediction is resized onto the GT pixel grid (nearest-neighbour for masks) before scoring.
Type contract
ProbeData.kind ∈ {depth, binary_mask, instances, points}. Each metric declares the kinds it accepts, and a mismatch raises an error rather than producing a number.
Failures
When GT fails (e.g. SAM 3 finds nothing), the row gets status=error and is left out of n. Under fail_fast: false the run carries on past failures.

Fidelity gates (wmeval/gates.py)

GateMeasurementFails whenUsed by
scene_preservationMean |output − input| / 255 over pixels outside the predicted region (dilated by dilate px; points are drawn as disks of that radius)> 0.15all except depth (dilate 5 for masks, 25 for dots)
instruction_complianceArea fraction of the marked region, or the number of decoded pointsarea ∉ [0.0005, 0.9]; points < 1 (kp) or < 2 (pose)all except depth
temporal_stabilityMean absolute frame diff (0–255) over the last 1.0 s, stride 2> 10 (depth: 12)all

Invalid rate = gate-failed rows ÷ scored rows. The report prints it next to every score. Invalid rows are still included in the headline means: _metric_stats filters on status == "ok" only. Aggregates are the mean and population std. There are no confidence intervals.

Generation-side conventions shared by every prompt

6 s, 16:9, 720p. Camera locked off. The overlay must be in place by {settle_s} and then held still. The instruction text is deliberately kept out of the prompt: only the parsed {relevant_objects} reaches the model, so counterfactual and adversarial instructions cannot be acted out. Generation-time checks (playable, min 24 frames; changed, reported but not enforced) decide whether a clip enters the manifest. They are not scores.

Per-probe measurement

Instance segmentation · instance_seg

Scenescored
Ask
Mask each object in {relevant_objects}, one at a time, in its own opaque, fully saturated colour. Everything else, including the robot arm, stays photographic. Negatives: outlines, gradients, pastels, white/black/grey overlays.
Ground truth
SAM 3 (facebook/sam3) text-prompted with gt_prompt from semantics (fallback: "object on table", "robot arm"). Thresholds: score ≥ 0.5, mask logit 0.5, area ∈ [0.001, 0.2] of the frame, dedup IoU 0.8, ≤ 20 instances, ≥ 1 required.
Extractor
color_instances: keep pixels with S ≥ 0.80. Find peaks in the hue histogram (the colours the model actually used), assign each pixel to its nearest peak, then split each colour into connected components. Components must cover 0.001–0.1 of the frame; ≤ 20 kept. White, black and grey paint cannot be detected.
Readout
last_frame. Oracle ranked by mean_iou.
IoU matrix pred × truth → greedy one-to-one match by descending IoU (pairs with IoU 0 never match) mean_iou = Σ matched IoU / max(n_pred, n_truth) ← headline; unmatched masks on either side cost score matched_iou= Σ matched IoU / n_matched fg_iou = IoU(∪pred, ∪truth) hit = matched pair with IoU ≥ 0.5 precision = hits / n_pred recall = hits / n_truth f1 pq = Σ hit IoU / (hits + ½·FP + ½·FN) both sides empty → 1.0; one side empty → 0
Pilot: n=17 (3 GT errors), invalid 35% (4 scene, 2 compliance). Readout 0.114, oracle 0.193, null 0.023. Valid-only mean is 0.168 (n=11) and invalid-only 0.017, so the gates do separate real failures here.

Depth perception · depth_perception

Scenenot discriminative yet
Ask
Replace the photograph with a grayscale depth map, near = bright and far = dark. No colormap.
Ground truth
Depth Anything 3 (DA3-LARGE-1.1), relative depth with larger values further away.
Extractor
gray_depth: luminance after a 5 px median blur, depth = 1 − L, a 2nd–98th percentile clip, then rescaled to [0, 1].
Readout
most_static over the last 2 s. Oracle ranked by delta1. Only the temporal gate applies.
valid = finite ∧ gt ∈ [0.001, 1000] ∧ pred ∈ [0.001, 1000] align (scale_shift): least-squares pred' = a·pred + b fitted to gt ratio = max(pred'/gt, gt/pred') delta_k = mean(ratio < 1.25^k), k = 1,2,3 ← delta1 headline abs_rel = mean|pred'−gt|/gt sq_rel = mean (pred'−gt)²/gt rmse rmse_log silog = 100·√(mean(d²) − mean(d)²), d = log pred' − log gt
Problems. (1) The input photo scores δ¹ 0.357 against Veo's 0.359. After an affine fit, δ¹ on a [0,1]-normalised field barely separates a depth map from scene luminance. (2) Bright = near reads like inverse depth, but the fit is done in depth space. The usual MiDaS/DA convention is an affine fit in disparity. (3) Latent bug: if the fit makes pred' negative, ratio is negative and counts as a δ hit, and the log terms become NaN. This did not occur in the pilot. (4) The percentile clip sets the nearest ~2% of pixels to 0, and pred ≥ 0.001 then drops them, so the closest surfaces are never scored (valid_frac 0.957). (5) No gate checks that the output is actually a grayscale image.
Pilot: n=20, invalid 0%. δ¹ 0.359 → 0.400 oracle; δ² 0.653; δ³ 0.836; abs_rel 0.472; SILog 45.1.

Active object detection · active_object_detection

Interactionoverlaps T1
Ask
Mask {relevant_objects}, described as "the object the robot is currently acting on", in one flat saturated colour.
Ground truth
SAM 3 on gt_prompt (fallback "object"). Same thresholds as T1, but ≤ 4 instances.
Extractor
active_color_instances, a copy of T1's decoder. ≤ 4 instances.
Readout
last_frame. Oracle ranked by mean_iou.
All T1 mask metrics (same greedy matching, mean_iou headline), plus: centroid_hit = fraction of truth masks whose centroid pixel lies inside ∪pred ← "did it mark the right object"
Problem. Semantics returns a target and a destination ("scissors" + "container"), and both feed relevant_objects and gt_prompt. Mean n_truth is 2.06, and the GT matches T1 exactly on 14 of 17 items. To measure the active object, both prompt and GT should use the target phrase only.
Pilot: n=17, invalid 29% (all scene preservation). mean IoU 0.088 → 0.143 oracle, null 0.023. centroid_hit 0.446 (oracle 0.461). Valid-only mean IoU 0.105.

Robot keypoint detection · robot_keypoint_detection

Robot statemetric inflated
Ask
A small, saturated dot on each rotating joint from base to gripper, each a different colour, and nothing else marked.
Ground truth
RoboPEPP (Panda, ViT-B, 224 px) produces 7 2D keypoints. Bbox from robot_bbox meta, else the full frame. Intrinsics from intrinsics meta, else f = 1.2·max(H,W) with a centred principal point. In the pilot, bbox = None and intrinsics were estimated.
Extractor
color_points: saturated blobs with S ≥ 0.5, V ≥ 0.2 and area 8–20000 px. No palette, ≤ 32 points, centroids returned.
Readout
last_frame. Oracle ranked by pck. Gate dilation is 25 px.
greedy one-to-one match by ascending pixel distance (no distance cap, no labels) τ = 0.05 · image diagonal pck = #matched with d ≤ τ / n_truth ← headline (= recall) precision = hits / n_pred f1 mean_dist = mean matched d / diagonal score = mean over truth of exp(−d_nearest / τ) (soft, unmatched)
Problems. With no palette, any saturated scene object counts as a dot. The input frame alone yields about 24.5, and the output 27.5. Every one of the 7 GT joints gets matched to its nearest blob, so PCK rewards clutter. Clips that failed the gates score higher (0.286) than valid ones (0.253). Without labels the metric also cannot check which joint a dot belongs to. Separately, 12% of GT points lie outside the image.
Pilot: n=20, invalid 35% (all scene preservation). PCK 0.264 → 0.479 oracle, null 0.214. Precision 0.065. Mean distance 0.127 of the diagonal.

Robot pose estimation · robot_pose_estimation

Robot stateGT suspect
Ask
A red dot (#e6194b) on the gripper centre and a green dot (#3cb44b) a short fixed distance ahead of it along the pointing direction.
Ground truth
Two RoboPEPP keypoints, by default the last two: index 6 (end effector) and index 5 (the joint behind it). Same bbox and intrinsics defaults as T6.
Extractor
pose_points: the largest blob near each palette colour (±22° hue), so the order is red then green.
Readout
last_frame. Oracle ranked by pose_score.
pos_err = ‖pred_red − gt_ee‖ / diagonal (1.0 if missing) θ = angle between (green − red) and (gt_ref − gt_ee), folded: min(θ, 180°−θ) ∈ [0°, 90°] heading = 1 − θ / 90° pose_score= exp(−pos_err / 0.05) × heading ← headline; 0 if either dot missing pos_pck = 1[pos_err ≤ 0.05]
Problems. 10 of 20 GT poses have a point outside the frame (e.g. y = −251). The GT vector points backward (end effector → joint behind) while the prompt asks for a forward marker. That only works because the angle is folded, and the fold also means a heading drawn exactly backwards scores perfectly. Keypoints 6 and 5 are close together on a Panda, so the GT angle is noisy. With τ = 0.05 and mean pos_err 0.22, the position term is about 0.012, so pose_score is almost entirely a position measure.
Pilot: n=20, invalid 10%. pose_score 0.057 → 0.080 oracle, null 0.007. Angle error 50.7°, pos_err 0.220, pos_pck 0.10.

Grasp region segmentation · grasp_region_seg

InteractionGT blocked
Ask
Paint the graspable part of {relevant_objects} in one flat saturated colour. Clips were generated in the pilot.
Ground truth
DA3 relative depth × depth_scale (1.0, a convention), back-projected with estimated intrinsics into a point cloud, z ∈ [0.05, 2.0] m. AnyGrasp then predicts up to 10 grasps, each projected as a 7 px line (or as points or a hull) to form a binary mask.
Extractor
color_mask: S ≥ 0.6, V ≥ 0.2, any hue, cleanup 5 px, area 0.0005–0.9, union of all blobs.
iou (headline) dice precision recall f1 boundary_f1 = F1 of 1-px outlines, each matched within a dilated (3 px) band of the other area_pred, area_gt as frame fractions
Problems. No AnyGrasp licence or checkpoint (only robopepp_panda.pt is in checkpoints/), and the probe is excluded in eval.robotrustbench.yaml. The GT also covers the whole scene: it ignores relevant_objects, while the prompt asks only about task objects. That is the same scoping mismatch the README warns about elsewhere. AnyGrasp also expects metric XYZ, and scaled relative depth is not that.

What to do next

The midterm plan (curate, verify GT, finish tasks, freeze the pipeline, add models, analyse) still holds. The measurement fixes should come first, because they cost nothing to apply: the 120 clips and all GT are cached, so each fix is a re-score.

Fix the measurement (before adding data or models)
  1. Add a null baseline to the report.Score the conditioning frame, held still, through every probe and print it as a column beside readout and oracle. A result only counts once it beats this baseline. A per-frame null for the oracle would give an honest oracle gap.
  2. Keep only pixels the model changed.Intersect the extractor input with |output − input| > ε before colour decoding. This removes the scene's own saturated objects for T1, T5, T6 and T7, and does the job README's "Calibrating the extractor" section describes.
  3. Rework the keypoint metric.Use Hungarian matching with a distance cap, make F1 (or PCK with a penalty for extra points) the headline, and add a fixed palette per joint so identity can be checked. Then decide whether the drift claim in the midterm holds up.
  4. Repair RoboPEPP GT.Pass DROID's camera intrinsics and a robot bbox through manifest meta. Flag or drop off-frame points. Check which Panda keypoint indices give a meaningful heading. Make the GT direction match the prompt's forward marker and remove the 90° fold, or justify keeping it.
  5. Rework depth scoring.Fit the affine alignment in disparity space, guard against non-positive aligned values, keep the nearest pixels, and add a rank metric (Spearman or ordinal error). Add a gate checking that the output is grayscale. Then check whether Veo beats the null at all.
  6. Separate active object from instance seg.Give T5 the semantics target only, in both its prompt slot and its GT prompt. Optionally widen T1 to all objects on the table so the two tasks measure different things.
  7. Finish the gates and stats.Report valid-only means and a per-gate breakdown (the midterm says this was not done), calibrate the thresholds on a labelled set of clips, and add bootstrap 95% CIs.
Then the midterm plan
  1. Curate the benchmark subset and verify GT.Choose items with a named target that SAM 3 can ground and on-frame RoboPEPP points, and review each GT preview .png by eye. Write semantics_overrides.json.
  2. Unblock grasp GT.Choose AnyGrasp (licence) or an open model (GSNet, GraspGen, Contact-GraspNet). Scope the GT to the target's SAM 3 mask, and use metric depth if DROID provides it.
  3. Decide on contact detection.DROID trajectories include gripper state, which RoboTrustBench drops. Join on source_traj_id to recover it, or cut the task.
  4. Add models.Write command backends for Wan2.2 and HunyuanVideo, plus a non-Fast Veo 3.1, and test each with limit: 1. Freeze prompts, readouts and thresholds before the full run.
  5. Failure taxonomy and release (O4).Use gate reasons, oracle frame indices and per-scenario splits as the raw material.

Everything else, briefly

wmcore

Shared registry (@register), plugin discovery via marker files, manifest schema, YAML config, video I/O, and stratified_sample (largest-remainder sampling by category).

wmgen

Frame sources, an optional llm_slots semantics stage (DeepSeek, cached per sample, overrides file), template prompts with requires checks, and backends http_job, command and local_dir. The clip store warns on prompt drift and never pays twice. Has a dry run. Runs serially with no resume.

Backends

veo3 (Gemini predictLongRunning, model veo-3.1-fast-generate-preview) and local. No open-weight backend yet.

Data

fetch_robotrustbench.py pulls all 1,207 items into frames + meta.yaml. The pilot is fixed to 20 IDs in configs/pilot_ids.txt (9/6/4/1 across scenarios A–D).

Per-probe tools

Each module has preview.py (rebuild and view GT) and scan.py (per-frame score curve, readout vs oracle). Useful for the GT-verification step.

Third party

third_party/RoboPEPP and third_party/depth-anything-3 are vendored clones. Torch-heavy dependencies sit in each module's own requirements.txt.

Code health

No tests. Code is duplicated: the mask metric and colour decoder (T1/T5), the DA3 wrapper (T2/T3), and the 252-line RoboPEPP model.py (T6/T7). Moving them into a shared module would stop the copies drifting apart.
